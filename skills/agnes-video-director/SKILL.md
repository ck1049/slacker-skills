# Agnes 视频导演

把用户的创意或参考图转成可直接粘贴的提示词，并保持界面设置、参考素材和镜头时长一致。默认交付简体中文；用户仅要提示词时，不要求密钥，不提交生成任务。

## 先确定实际输入

- 保留用户指定的模型、网站、时长和画幅。未指定型号时，可建议用 Flash 做初测，但不能声称它一定更快或质量等同付费版。
- 打开并查看实际参考图；不能只凭文件名或其他版本的角色图描述外观。记录脸型、发型、服饰主色、饰品和画风等可见特征，不编造背面结构或未见配件。
- 区分网站界面、官方 API 和底层模型能力。网站有更小上限时按实际界面交付；没看过网站时，不假定它暴露了某个模式或参数。
- 时长等事实参见 [官方约束与接入](references/official-contract.md)。用户要求超出上限时，解释限制并重排节奏，或按需求拆镜；不要仅把超限时长写进提示词。

## 模式选择

要求从原图姿态和构图开始时，优先首帧控制；只要求角色身份、希望换场景或构图时，选择参考模式。没有图时用文生视频。图生视频是宽泛界面名称，不能据此推断实际模式。

参考模式按上传顺序标明每张图用途；官方 API 提示词使用 `<Picture 1>` 等标记。网站若有自己的素材标签，使用其实际标签；网站未提供标签时写“上传的第一张参考图”。首帧模式写“从上传首帧开始”，不混写参考模式的素材绑定。

## 写提示词

围绕主体与环境、动作变化、运镜、视觉风格、声音意图和一致性组织内容。只写对当前镜头有用的细节，不靠反复堆叠“完美、顶级、8K”代替具体指令。

以下是本技能的创作建议，并非模型保证：

- 初次测试用单主体、一条主要运镜和少量可观察动作。根据用户要测的能力安排转头、手部接触、迈步或衣料运动，不强制所有镜头都用同一套动作。
- 短片写清起始状态、动作发展、结束姿态。分段时间要连续、总长匹配设置；时间码是节奏指导，不承诺逐帧精确。
- 手部动作说清左右手、接触对象和最终位置；运动先后关系比同时堆叠多个动作更易评估。
- 推镜给出起止景别；不要在同一时刻要求固定镜头和环绕，也不要用纯图像放大描述替代真实运动。
- 图中细节无需逐项复述；挑选最影响身份的一组特征，说明必须保持稳定。小饰品和纹样可作为成片检查重点。
- 声音只按需求描述，不保证精确台词或一定无音轨。需要逐字配音时说明应做后期或单独验收。
- 避免长串否定词；把关键限制写进主提示词，不猜测网站有独立负面提示词字段。

## 交付形式

给出实际可设置的模型、时长、画幅和输入方式，然后给一个完整可复制的提示词代码块。路径、上传步骤、计费提醒和 API 参数放在代码块外。用户只要改稿时直接给改稿，不扩展为教程。

需要示例时读取 [12 秒角色测试](references/character-test.md)；示例只演示写法，换角色必须重新看图。默认不把任何角色设定固定为所有项目的默认值。

## 执行与验收

只在用户要求实际生成时进入执行。涉及收费时先核对当前站点费用、数量和总额，取得明确授权；既有授权范围内不要重复询问。不要把“免费模型”当作第三方网站免收费证明，也不要自动切换付费版或上传本地素材到公共托管。

接入规则与故障处理见 [官方约束与接入](references/official-contract.md)。本技能不自带生成客户端，也不冒充已连接的 API。

拿到成片后，区分技术验收和视觉验收：测实际时长、分辨率、是否可解码；观看开头、动作转折和结尾，检查脸、手、衣饰、动作落实和镜头连续性。未观看成片不能宣布保真通过。

迭代时保留原图和主要设置，每次优先改一个因素：换脸先减小转头幅度；手部失败先简化接触；动作拥挤先减少动作；只有推拉无肢体运动时明确一个主体动作。保留失败版本以便比较；这些是诊断建议，不是模型性能结论。

## 维护

约束核验日期记录在引用文件。再次回答“最新限制、费用、支持模式”或准备执行前，核对对应官方页面；网页不可访问时明确使用有日期的快照。不要混入旧版 v2.0 的帧数参数、其他模型上限或社区未经复核的参数。只有用户要求维护时才修改技能文件，不自动创建定时任务。
