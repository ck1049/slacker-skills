# Codex 聊天归档与清理

将一个明确聊天的原始 JSONL 保存为可核验的本地归档，再按用户授权清理该原文件。保留每个原始字节，包括图片数据、工具结果和尾部追加；交接摘要不能替代完整备份。

## 范围与入口

- 研究方法、检查大小、制作本技能不等于授权执行真实备份或删除。只处理用户指定的聊天与目录；不得批量清空 sessions、数据库、媒体、模型或凭据。
- 沿已有明确授权执行，不重复请求已给出的许可。没有删除授权时完成备份、回读核验和交接，止于可审阅结果；不要生成自动执行删除的启动器。
- 不从“最近修改的最大文件”猜聊天身份。优先使用当前运行时或聊天工具确认完整 thread UUID；在 `CODEX_HOME`（未配置时 `~/.codex`）的 `sessions`、`archived_sessions` 内按该 UUID 定位候选，再检查首条 `session_meta.payload.id`。路径与文件结构仍需本地核实。
- 只取文件清单、尺寸、首条元数据和回执；不要把多 GB 日志、Base64 或图片历史重新灌入聊天。既有归档只读研究，不运行其中写死路径的旧删除器。

首次实际使用先读 [执行与恢复](references/operations.md)。研究旧备份或判断压缩选择时读 [方法来源与改进](references/design.md)。交接可采用 [模板](assets/handoff-template.md)，只填当前真实工程事实。

## 工作顺序

1. **确认身份和影响。** 查看精确原路径、大小、目标盘剩余空间、已有备份及关联定时任务。归档/侧栏隐藏不等于释放日志；不要改共享 SQLite 来假装单聊天清理。关联自动任务可能再次写回旧聊天，记录实际状态；只有用户授权时才用应用工具暂停、迁移或删除它们。勿直接编辑其内部数据库。
2. **保存短交接。** 写清工程入口、正式采用文件与 SHA、待办、已提交任务 ID、暂停范围、自动任务状态、费用/授权边界及继续入口。记录“生成/下载/剪入/技术通过/用户认可”的区别。无明确新聊天创建请求时只准备交接文件，不自动新建聊天。
3. **流式快照。** 用现有 Python 执行随附 `scripts/archive_session.py snapshot`，输出到 Codex 状态之外的私密、空间充足目录，通常选大容量数据盘。优先已有 Python 3.14 标准库 Zstd；否则用 gzip，不为备份安装依赖。快照只截到开始时已有的最后完整换行，后续字节留待退出后补齐。
4. **完整回读。** 脚本核验压缩文件 SHA、完整解压后的字节数/SHA，再写回执；不靠“能打开压缩包”、文件大小或摘要声称备份完整。不要删除、重压旧合格归档来节省一点空间；重压须另有授权及独立核验。
5. **按授权离线收尾。** 活跃聊天不能当场删。把已复制到归档内的自包含脚本与命令交付给用户：完全退出 Codex 后运行 `seal`；默认只补尾核验，只有明确获准删除才带 `--delete-source --confirm-thread UUID`。脚本检查应用退出、独占锁住精确源文件，验证既有前缀、追加尾卷、回读全卷并持久保存回执后，才通过同一个文件句柄删除。进程未退、占用、改写、截断或验证失败时保留原件；不自动杀进程、不绕过锁、不反复等待。
6. **交付。** 分清 `SNAPSHOT_VERIFIED`、`SEALED_VERIFIED`、`SOURCE_DELETED`；说明实际压缩大小、原盘释放量与跨盘净节省，不把“备份好了”写成“已经删了”。所有归档、交接与回执保持私密，不提交到公共仓库。恢复只到新的普通文件，不覆盖 Codex 状态，也不承诺单个日志能重建应用界面。

## 验证与停止条件

新代码只在隔离小文件上测试，不能用真实聊天试删。随附行为测试覆盖追加尾部、损坏归档、错身份/改写前缀、文件占用、重新创建、跨目录搬迁及恢复。

一次指定聊天成功封存并按授权清理后即结束。停止旧聊天再次写入应由用户使用新聊天和显式任务迁移完成；不把备份技能变成常驻清盘任务。无法安全清理时交付已验证备份与具体原因，不猜删除成功。
