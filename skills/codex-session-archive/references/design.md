# 方法来源与改进

2026-10-31 研究了用户提供的既有视频制作聊天备份目录。以下是**历史回执记载**，不是本次重压或重新解压大归档的结果；可复用技能不携带真实聊天内容、用户名、项目身份或绝对路径。

## 旧实例证明了什么

- 开始快照为 11,267,011,442 字节；最终退出后原件为 11,267,545,016 字节。
- 初版 gzip 约 10.96 GB，后来用已有 Python 3.14 标准库 Zstd level 3、长距离匹配重压为 5,694,571,542 字节。仅首快照约节省 49.5%；这不是通用压缩率承诺。
- 最后追加 533,574 个原始字节，单独 gzip 为 305,690 字节。最终回执记录按“Zstd 快照、gzip 尾部”拼接核验全文件 SHA 后删除精确原件。
- 保留新聊天交接、定时维护任务隔离回执、恢复脚本；没有清共享 SQLite、制作媒体、账号设置或其他聊天。
- 清理器用 Win32 独占读/删除句柄，`SetFileInformationByHandle(FileDispositionInfo)` 标记该句柄删除，避免先校验 A、随后按路径误删 B 的竞态。

## 不照搬的部分

- **写死身份和路径**：改为完整 thread UUID、源路径、CODEX_HOME、目标目录参数，并验证 `session_meta`。不把最近日志当当前聊天。
- **先 gzip 再 Zstd**：有合适现成解释器时直接 Zstd，减少重复读取及临时占用。没有就用 gzip，不擅自下载。
- **绝对分卷路径**：新清单只用相对 basename，因此备份目录可搬迁。原路径仅保留作溯源，恢复不写回原处。
- **含糊的“备份完成”**：显式快照、退出后封存、精确删除三种状态；活跃日志追加和半条尾记录不会被误认为已覆盖。退出收尾保存所有尾字节。
- **删除恢复容易与 UI 混淆**：只承诺原始字节证据，不能承诺单文件恢复等于恢复所有聊天 UI/索引。归档侧栏也不等于磁盘清理。
- **数据与工具混放复用**：通用脚本不含个人目录、项目数据或凭据；实际备份内另存自包含工具和交接，保持私密。

## 适用边界

这是在现有本地日志上实现的备份工具，不是 OpenAI 官方删除/导入 API。官方资料只用于核实状态根目录的含义，具体日志首记录、锁、回执、压缩率来自本地观察和行为测试。

2026-10-31 已打开核对的 [OpenAI 官方高级配置文档](https://learn.chatgpt.com/docs/config-file/config-advanced)说明 `CODEX_HOME`（默认 `~/.codex`）保存本地状态。实施时仍需核实本机实际目录，不将 `history.max_bytes` 当作已验证的桌面 rollout 或共享数据库清理开关。
