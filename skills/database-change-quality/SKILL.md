# 数据库变更质量

让数据库结构和访问代码可读、可验证，并保留已有数据的正确性。先适配宿主项目，不把示例数据库、ORM 或版本命名推广为强制方案。

## 先识别已有契约

读取相关仓库说明、数据库配置、迁移历史、数据访问层和测试入口。确认引擎与版本、驱动、字符集/排序规则、时间和金额表示、命名规则、注释语言、迁移工具及部署流程。只读取判断所需配置，不输出秘密。

区分新库初始化、已有库升级、数据修复和查询调整。无法确定目标库身份或数据是否可丢弃时，先完成脚本和隔离验证；不要猜测并清库。沿用现有 ORM、查询生成器或 SQL 组织方式；只有当前任务要求架构调整时才替换。

## 写出可维护的结构和查询

- 一个表形成一个阅读块：建表后紧跟该表、字段和约束的说明；独立索引创建后紧跟索引说明。不要把全部注释堆在文件末尾。
- 注释说明业务意义、单位、可空原因、时间基准、索引用途，采用团队语言而非固定中文。支持数据库元数据注释时写入元数据；不支持时使用相邻 SQL 注释或项目维护的数据字典，不发明跨方言语法。不在注释中写入秘密或个人敏感数据。
- 对受影响表、字段和索引检查注释完整性，包括约束生成的索引；无法独立注释的对象就近说明。数据库生成名称可能变化，不能盲猜标识符或为了补注释修改约束语义。
- 主键、唯一性、外键、非空和检查约束表达真实业务不变量；不能只依赖应用的先查后写。并发消费、库存扣减等使用原子条件与事务，并验证受影响行数。
- 参数值通过驱动或框架绑定；动态标识符必须来自受控映射。查询、更新、删除保留权限与租户约束，不能在通用 CRUD 重构中丢失这些条件。
- 复杂 SQL 保持分行、明确别名和结果类型，放在项目约定的查询资源或数据访问层，不要求所有语言使用 mapper XML。ORM 不得掩盖 N+1、无界结果、锁顺序或未知提交结果。

## 保留数据的变更

已应用或已发布的迁移默认不可改写；按宿主工具规则追加可追溯迁移，不强制数据库版本等于应用版本。只有用户明确允许、尚未发布且已核实所有受影响环境时，才合并初始化基线。存在开发数据时也先备份、试恢复并明确基线转换，不能直接删除历史表或卷。

破坏性变更前明确兼容窗口、回填、锁影响、失败恢复和停止条件。必要时先扩展结构、迁移读写，再移除旧结构。不可逆数据变更不能用形式上的 down 脚本冒充可回退；验证备份恢复或向前修复。提交超时或连接中断后先核对真实状态，避免盲目重放非幂等操作。

## 验证与交付

使用目标引擎兼容版本，在授权的隔离库执行：新库初始化；若涉及升级，再从代表性旧结构和数据升级，检查数据、约束与迁移历史。查看目录元数据确认注释真正落库。测试权限隔离、重复请求、并发竞争及失败恢复等受影响风险。

轻量数据库或内存模拟只证明其自身行为，不能替代目标引擎的事务、锁、方言及迁移验收。无法运行目标引擎时交付脚本、静态结果和未验项，不声称完成运行验收，也不擅自安装或启动生产服务。

审查格式和真实差异，记录测试引擎/版本、关键结果及恢复限制。不要为纯注释修改扩张成全库重构或无关索引优化。

## 按实际方言核对官方依据

以下入口于 2026-09-19 核对；实施时切换到项目实际版本，链接不构成升级要求。

- [PostgreSQL COMMENT](https://www.postgresql.org/docs/current/sql-comment.html)：支持的对象、元数据与注释可见性。
- [MySQL CREATE TABLE](https://dev.mysql.com/doc/refman/8.4/en/create-table.html)：表、列与索引定义中的方言选项。
- [SQLite SQL](https://www.sqlite.org/lang.html)：实际支持的语法；不能照搬其他引擎的 COMMENT ON。
