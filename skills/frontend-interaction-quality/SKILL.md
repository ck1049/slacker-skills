# 前端交互质量

把页面的生命周期和实际用户操作一起设计，避免只检查组件能否渲染。先读取项目规则、现有路由与设计系统、支持的浏览器/视口、认证和数据缓存边界、测试工具与近期相关实现；不预设框架、路由库或页面结构。

## 先确定状态归属

为当前变更列出少量重要状态：页面/项目选择、未提交草稿、请求中状态、错误、服务端数据、敏感输入。明确每项在切页、返回、刷新、退出和账户切换后应保留还是清理。沿用已确认行为，只有无法推断且会改变用户体验的分歧才询问。

- 草稿可以放在路由上层、显式状态容器或按需保留的页面中；根据内存、请求量和恢复要求选择。不要把始终挂载所有页面视为通用答案，也不要在未要求跨刷新恢复时自动写入持久存储。
- 登录身份改变或会话失效时，清理属于旧身份的草稿、缓存、错误和请求结果。缓存键至少包含实际数据隔离维度；仅用相同的项目 ID 或会话 ID 不足以隔离账户。
- 密码、密钥和令牌不随普通草稿持久化或进入日志。离开页面是否清除未提交敏感输入按产品策略决定；隐藏组件不等于已经清除输入。

## 导航与可访问性

用现有路由实现可识别的页面地址、刷新和浏览器前进/后退；解析非法地址及无权限入口时采用明确回退。客户端隐藏入口不是服务端授权。

为当前导航提供选中语义，保持标题、可访问名称和焦点顺序一致。路由变化后按交互上下文管理焦点，不让轮询或局部更新反复抢焦点。跳转主要内容的链接不应误触单页应用路由。用链接导航、按钮执行动作；可点击容器不能替代完整键盘交互。

隐藏页面不能仍占布局、接收焦点或暴露相冲突的交互元素。表单标签、错误说明和处理进度要能被辅助技术识别；避免把所有普通更新都做成高优先级播报。

## 异步真实生命周期

请求的开始、成功、失败、取消和结果不明分别处理。把防重复操作和忙碌计数绑定真实操作，而不是仅绑定某个子组件的挂载周期；切页或切换编辑对象不能让仍在执行的保存提前变成“已完成”。

迟到的响应需要核对账户、编辑对象和请求代次，不能覆盖用户后续选择。取消网络等待也不证明服务端写入被取消。需要重试时保留协议要求的请求标识和原始内容，不能随意生成新标识造成重复副作用。

已有操作在切页后继续时，给用户可理解的进度与返回入口。是否禁止退出由产品契约决定；不要仅靠禁用按钮声称已解决服务端幂等或任务恢复。

## 验证真实交互

按此次风险选择测试，而非对所有改动堆砌清单：

- 页面切换、直接地址、前进/后退后，草稿与选择符合约定。
- 保存中切页或卸载编辑组件，进度持续到真实完成；失败后能恢复操作。
- 账户切换后旧响应不会污染新账户，即使对象 ID 相同。
- 键盘可抵达主要功能，隐藏页不参与交互，错误与进度可感知。
- 在产品支持的桌面、窄屏及临界宽度实测，检查横向溢出、长内容、触控目标与遮挡；截图和 DOM 几何可辅助判断，不能只根据 CSS 断言已适配。

运行现有类型/静态检查、构建及受影响测试，再用实际浏览器走关键路径。浏览器不可用时如实标记视觉验收未完成。不要使用真实付费操作、真实秘密或破坏性数据来完成 UI 验证；优先隔离夹具与测试账户。

## 条件参考

- 使用 React 并调整组件身份、`key` 或条件渲染时，阅读 [状态保留与重置](https://react.dev/learn/preserving-and-resetting-state)；其他框架按对应生命周期实现相同业务边界。
- 调整导航与焦点时，阅读 [W3C 焦点顺序说明](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html)。这不是完整无障碍合规认证。
