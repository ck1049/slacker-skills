# Python 维护代码质量

以可读代码和可验证的失败行为替代一次性脚本习惯。默认只改变本次任务涉及的代码，不重装运行环境，不迁移包管理器。

## 识别项目后再实现

检查项目规则、Python 支持版本、`pyproject.toml` 或等价配置、锁文件、虚拟环境、测试和 CI 入口。使用项目已有解释器与执行方式；不要假设 `python` 指向正确环境、某个 Shell 可用，或依赖可以全局安装。

采用已有格式化、lint 和类型工具及配置。没有配置时以 PEP 8 为起点，工具选型保持最小；Ruff、Black、mypy、Pyright 是可选方案，不同时引入互相冲突的格式规则。升级工具或使用新语法前检查项目最低 Python 版本。注释语言、作者和时间规则来自宿主约定，不注入个人身份。

## 结构和类型

- 将参数解析、业务转换与外部 I/O 分开；入口保持薄，复杂操作拆成有明确输入输出的函数，不为小脚本建立空层级。
- 函数和分支正常分行，避免一行塞进多个操作；嵌套、长表达式与推导式以能快速理解失败路径为限。格式器通过后仍检查可读性。
- 已知结构使用适合项目的 dataclass、TypedDict 或验证模型；动态键值集合可继续用字典。公共入口和有风险的操作标注类型，不用无处不在的 Any 掩盖边界。
- 类型注解不进行运行时验证。对 JSON、环境变量、CLI 和外部进程输出执行所需的结构、取值和长度校验；不要把 cast 当验证。
- 注释解释幂等条件、资源归属和恢复假设，不重复代码字面含义。

## 异常、进程和资源

- 捕获能处理的具体异常；边界统一映射诊断信息与退出码。保留异常原因，不用空 except 或默认成功掩盖失败。清理写在上下文管理器或 finally 中，清理异常不能悄悄覆盖主要错误。
- 子进程优先用参数列表与明确的工作目录、超时、退出码处理；只有确实需要 Shell 语义时才启用 Shell 并按实际平台引用参数。不要把 JSON 序列化当命令转义，也不要把用户字符串拼成命令。
- 根据所调用程序核对 Windows 批处理、进程树终止和编码等平台差异；列表参数不是所有平台与文件类型的通用安全保证。超时后明确子进程是否仍在运行，不能假设操作已撤销。
- 外部输出按预计体积选择捕获或流式处理，防止无界内存；日志脱敏，不输出凭据、完整环境或敏感原始输出。文本协议显式使用其约定编码。

## 文件操作和恢复

破坏性文件操作先解析并检查目标位于授权根内；使用路径对象和路径包含关系，不能用字符串前缀判断目录边界。考虑符号链接、目录联接和检查到使用之间的竞态；如果输入可被并发恶意替换，单次 resolve 不足以提供安全隔离，应采用受控目录和平台适合的文件操作机制。

维护操作按风险设置预检、执行、核验和恢复阶段。重要覆盖写优先写同一文件系统的临时文件再替换，并按实际需求处理权限与持久化；原子替换不等于断电持久性。涉及数据库、远程请求或多文件操作时记录可恢复状态，不能假设文件原子性覆盖整个任务。

不可逆操作需已有明确授权和验证过的目标。对结果不明的外部写入，先查询状态，再按幂等契约决定重试；为重试设次数、截止时间和终止条件。dry-run 应只读且说明不能验证的部分，不把它当真正执行成功。

## 与风险对应的验收

运行宿主配置的格式、lint、类型检查和行为测试。为变更涉及的风险选择测试：恶意或带空格路径、权限不足、进程非零退出与超时、损坏输入、部分写入、重复执行和恢复。不触发真实收费或生产破坏来证明测试。

临时目录和夹具用于隔离；Mock 只证明约定的交互，进程/编码/文件系统兼容声明应有实际目标环境证据。无法取得相应环境时注明局限。报告修改目的、验证结果和未验证平台，不因测试通过承诺所有环境均适配。

## 官方依据

以下入口于 2026-09-19 核对；实施时选择项目 Python 版本的文档，不强迫升级。

- [PEP 8](https://peps.python.org/pep-0008/)：代码布局与项目一致性。
- [typing](https://docs.python.org/3/library/typing.html)：类型注解与运行时边界。
- [subprocess](https://docs.python.org/3/library/subprocess.html)：参数、超时和平台安全注意事项。
- [pathlib](https://docs.python.org/3/library/pathlib.html)：路径解析与文件系统操作。
- [Ruff 配置](https://docs.astral.sh/ruff/configuration/)：采用 Ruff 时的配置发现与目标版本，不作为必装依赖。
