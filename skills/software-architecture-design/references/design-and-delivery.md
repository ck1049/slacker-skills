# 架构与交付清单

按项目风险选择条目，明确不适用，不要求每个小项目具备全部设施。

## 技术与系统边界

技术表写明“组件/职责/决定状态/理由/替代方案/兼容验证”；前端、后端、持久化、异步任务、存储、部署、观测和构建工具按需覆盖。先考虑团队技能和运维代价，再比较语言生态；多语言或多服务应有具体收益。

图示与文字说明调用方向、身份传播、数据所有权、事务边界、状态的权威来源、部署单元。性能指标绑定硬件、数据量、并发和场景，区分上游等待与本服务耗时。版本在实施时从官方发布及兼容性资料核验并锁定，不把浮动镜像或旧研究当生产基线。

## 数据、异步操作与扩展

有异步或收费副作用时：先持久化意图，再提交；记录上游标识和未知状态；检查数据库并发约束、队列/SDK/客户端隐式重试；结果不明先查询或核对，不盲目重发。下载失败与生成失败分离，不承诺未经证明的端到端恰好一次。

明确取消、超时、崩溃恢复、重放和重复事件语义。设计迁移、保留/删除、导出、备份与恢复；日志和测试证据脱敏，不把个人凭据或生产数据纳入仓库。

存在插件时，区分声明式资源与可执行代码、宿主权限与业务权限，确认导入、版本兼容、启停与回退。参考工程只读授权不允许在原目录安装或运行会产生文件的工具。

## 仅在 AI/Agent 项目适用

澄清自主程度、工具授权、费用/次数预算、流式交互、会话持久化、跨会话记忆及产品 Skill 的开放范围。不要把开发助手技能与产品内 Skill 混为一谈。

会话历史、压缩摘要、项目记忆是不同层；说明长期记忆的提议、确认、查看、修改/删除及缓存失效。模型输出和导入资料不能自行扩大工具权限。含脚本 Skill 是否执行必须单独明确，不默认授权宿主代码运行。

调用前按实际用户/账户/额度池核验身份和预算；并发授权需要原子约束。上游成功、产物下载、技术校验和用户视觉验收分别记录。模型文档、账号权限、适配实现与真实验证分别列状态；真实付费验证须在明确平台、模型、次数和预算范围内。

## 开发与交付

里程碑包含进入条件、依赖、可运行/可评审交付和可观察验收。独立模块先定契约，再并行；实现者自评不代替独立审查。修复后针对新版本复查，不能沿用旧提交的通过结果。

建立质量问题清单并完成核实、修复、测试、复查；既记录剩余技术债，也给出延期理由。达到验收、门禁通过、阻断项清零且其余意见有处置后收敛，不无限扩大重构。

发布设计澄清目标系统/架构、在线或离线包、缺少运行环境时的处理、升级与恢复范围。稳定版本的主分支 SHA、tag、Release 与资产对应；附件包含版本清单、校验和、许可和中文说明，不静默替换已发布资产。

一键入口不意味着自动提权、登录或解决所有系统依赖。离线包须在约定前置条件下断网验收，不能暗中下载依赖；在线模型服务仍需网络。容器启动不等于健康检查通过。

升级前一致性备份，失败不删数据；应用回退与数据库回退分开验证。恢复旧备份可能丢失新写入，须说明并明确处置。没有测试过的平台、恢复路径、账号权限或质量效果必须标未验证。
