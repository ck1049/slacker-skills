# 稿件流程、恢复与稳定维护

## 状态和唯一来源

区分计划、初稿、审改中、当前定稿和已发布；通过评审后才晋级定稿。已发布是外部动作的实际结果，不能仅因生成文件就标发布。并列版本明确哪份有效，旧稿不混进连续性事实。

给章节稳定 ID；调整标题不改变 ID，拆并章节保留映射。记录正文位置、版本/摘要、评审、台账更新和发布记录。摘要可检测是否变更，却不能恢复正文；文件更新时间也不能证明它是正确版本。

每批写作顺序：恢复资料 → 章卡 → 小批初稿 → 审改/复验 → 晋级定稿 → 台账/交接 → 保存可恢复版本。未解决的设定问题阻断依赖它的后续定稿；可以继续其他不依赖它的规划，不无限扩写问题。

## 备份与中断恢复

写前确认文件归属，不覆盖用户已有稿。保留原稿与可追溯修正；可使用已有 Git 或时间戳快照，不为了写作强迫迁移工具、创建远程仓库或上传私稿。

备份正文、冻结设定、大纲、状态、伏笔、评审和变更，而非只备正文。至少一份备份与正在编辑的文件分开；复制到同一磁盘能防误改但不能防设备损坏。需要长期保存时，用户选择其认可的另一存储位置；没有执行或恢复验证不能称可靠异地备份。

在临时隔离目录试恢复一批文件，对照摘要和目录，再说明恢复了什么。不得为了测试删正式稿、回滚用户工作或触碰真实发布记录。暂停后从唯一当前版本恢复，不用聊天中的模糊记忆重构过去。

恢复检查：最近定稿及评审摘要匹配，关键物件/伤势/时间/知识继承正确，未兑线索仍有计划，下一章未完成动作清楚，冻结变更已同步。发现摘要不符先定位差异并复审，不能把哈希更新当质量检查。

## 副业的可持续节奏

先记录实际试写、审改和资料核查时间，再估算每周可完成的定稿；不要用模型输出速度当作者完整工作速度。存稿量以通过审改的章数计算，粗稿不算可发布库存。

设置固定写作窗口、审稿窗口和余量。低产量时缩小章节批次、保留主冲突、减少无效调研，不删掉审核；不得因为要赶日更而宣布质量合格。长时间停写先恢复工程，必要时短读最近两章，别重写全书开头拖延。

疲劳与中段卡顿先诊断：人物目标不够、信息与资源没有变化、支线无交点、谜底缺失、专业资料不足、段落表达问题或计划产量过高。前五类不是换几个词能修，最后一类不是剧情缺陷。修改最小必要范围，不为一个场景换整个题材。

## 发布准备（只在任务要求时）

核对目标平台现行内容/AI 使用披露/更新与签约规则；对合同中的授权范围、独家、版权、退出、收益、违约和既有发布要求列出实际条款与待确认项，不从记忆推断法律效果，不替用户签约。

确认笔名、简介、读者版目录、当前定稿、作者身份与发布许可。评论回复、上传、注册和联系他人需要相应授权；“写小说”不自动授权公开发布或接受合同。没有平台就先准备本地读者版，不阻断创作。

作品简介、推荐语和运营记录必须真实；不伪造读者评论、成绩或收入。未经核验不建议多平台重复发布，以免与独家约定冲突。

## 少维护靠稳定契约

把通用技法与作品特例分开：词库按条件扩展，灯/系统/某角色留在作品工程。Skill 更新由反复出现的失效机制或确实缺失的流程驱动，不因为首作某个细节失败就新增强制规则。

维护顺序：定位问题 → 判断作品稿/台账/通用 skill 哪层失效 → 最小修正 → 一个相关案例和一个不同题材案例复核 → 记录兼容性。新增模板字段说明谁维护、何时更新、能解决什么，否则不加。

保持入口简明，按问题读取参考，不要求每章填写全部材料。模板允许短篇合并与不适用说明，但不能省略会影响本篇因果的约束。可以建立版本与变更记录，不承诺技能一次写完永远无需维护。
