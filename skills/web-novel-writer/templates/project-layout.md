# 新作品工程

建议为长篇建立独立目录，不把正文塞进通用技能仓库：

```text
作品工程/
  README.md                  # 定位、进度、阅读入口、继续方式
  AGENTS.md                  # 续写约定、资料优先级、目标尺度
  planning/
    premise.md               # 选题与原创差异、工作节奏
    story-bible.md           # 世界观、人物、规则压力测试、冻结版本
    outline.md               # 全书因果、卷/支线、关键真相与结局
    chapter-cards.md         # 已细化的章卡及下一章入口
    style-and-references.md  # 自有文风、参考技法、不复制内容
    research-log.md          # 影响因果的事实、来源/架空/待核
  continuity/
    state.md                 # 当前人物、时间、物件、知识与关系
    clues.md                 # 作者答案、读者证据、兑现计划/实际进展
    handoff.md               # 最近定稿摘要、续写必须继承的事实
  manuscript-control.md     # 当前版本、章状态、备份与恢复验证
  manuscript/
    001-章节名.md
  reviews/
    prewriting.md            # 开写前压力测试与原创/规划检查
    001-review.md            # 逐章问题、修正、复验与文本摘要
  changes/
    log.md                   # 冻结后变更，没变也明确记录
  drafts/                    # 按需要保留初稿；不视为定稿事实
```

短篇可合并文件；不要建立大量无内容占位。章卡与台账用前述模板，原始资料有版权/隐私时不提交。读者只需阅读 manuscript；planning、continuity 和 reviews 含剧透。

## 冻结变更单

变更 ID、日期、旧/新内容、原问题证据、局部修稿为何不足、受影响章节/人物/伏笔、是否已发布、授权边界、修复方式、复验结论。未变更时记录“冻结版本维持，局部表达修正见章评”。

## 完成交付

能复原的作品规划、已冻结的核心、通过本轮审改的开篇、与正文相符的状态、未兑线索、下一章卡、审稿证据和明确进度。目录齐全而内容空白不算开启创作。
